# ოჯახის ბიუჯეტი

ოჯახის ბიუჯეტის დაგეგმვისა და კონტროლის აპლიკაცია გიორგისა და ნინოსთვის — შემოსავალი, გერმანიაში აუცილებელი ხარჯები, საქართველოში გადასარიცხი თანხები (₾ → €), დანაზოგი და თითოეულის თავისუფალი ფული, ერთ ეკრანზე.

აპლიკაცია მთლიანად მუშაობს ბრაუზერში — **არ სჭირდება საკუთარი სერვერი თუ ბაზა**. მონაცემები ინახება თქვენივე ბრაუზერში (`localStorage`), ხოლო სურვილის შემთხვევაში შეგიძლიათ ჩართოთ **ავტომატური სინქრონიზაცია** კომპიუტერსა და სმარტფონს შორის (იხ. ქვემოთ).

---

## ⚠️ მნიშვნელოვანი გაფრთხილება

**თქვენი მონაცემები ნაგულისხმევად ინახება მხოლოდ ამ ბრაუზერში, ამ მოწყობილობაზე.** თუ წაშლით ბრაუზერის მონაცემებს, გამოიყენებთ სხვა მოწყობილობას ან ბრაუზერს (და სინქრონიზაცია ჩართული არ გაქვთ), ან რამე მოხდება მოწყობილობასთან — მონაცემები დაიკარგება, თუ წინასწარ არ გექნებათ **JSON ბექაფი** გაკეთებული.

➡️ რეგულარულად გააკეთეთ **პარამეტრები → მონაცემები → JSON ექსპორტი**. აპლიკაცია თავად შეგახსენებთ, თუ 30 დღეზე მეტია ბექაფი არ გაგიკეთებიათ. სინქრონიზაციის ჩართვა ამ საჭიროებას ამცირებს, მაგრამ არ ანაცვლებს — JSON ბექაფი მაინც ღირს.

## GitHub Pages-ზე გამოქვეყნება (ნაბიჯ-ნაბიჯ, არაპროგრამისტისთვის)

1. შექმენით ახალი **repository** თქვენს GitHub ანგარიშზე (მაგ. `family-budget`).
2. ატვირთეთ ამ საქაღალდის ყველა ფაილი და ქვესაქაღალდე repository-ის root-ში (ანუ `index.html` პირდაპირ repo-ს ძირში, არა ქვესაქაღალდეში).
   - შეგიძლიათ გამოიყენოთ GitHub-ის ვებ ინტერფეისის „Add file → Upload files" ღილაკი, ან `git push`, თუ იცით როგორ.
3. გადადით repository-ის **Settings** ჩანართზე.
4. მარცხენა მენიუში აირჩიეთ **Pages**.
5. **„Build and deployment"** სექციაში, **Source**-ში აირჩიეთ **„Deploy from a branch"**.
6. **Branch**-ში აირჩიეთ `main` (ან რომელ branch-ზეც ატვირთეთ ფაილები) და საქაღალდედ — **`/ (root)`**. დააჭირეთ **Save**.
7. დაელოდეთ 1-2 წუთს — GitHub ავტომატურად გამოაქვეყნებს საიტს. გვერდის ზედა ნაწილში გამოჩნდება ბმული სახით: `https://<თქვენი-username>.github.io/<repo-სახელი>/`.
8. გახსენით ეს ბმული — აპლიკაცია მზადაა! შეგიძლიათ დაამატოთ ტელეფონის მთავარ ეკრანზეც (Android-ზე Chrome-ში: მენიუ → „Add to Home screen").

**შენიშვნა:** თუ დააკოპირებთ ან გადაარქმევთ repository-ს, ან შეცვლით მისამართს, ბრაუზერი ამას აღიქვამს, როგორც ახალ საიტს — ძველი localStorage მონაცემები ახალ მისამართზე არ გადაინაცვლებს. ამიტომაც მნიშვნელოვანია JSON ბექაფი და/ან სინქრონიზაცია.

## 🔄 სინქრონიზაცია კომპიუტერსა და სმარტფონს შორის

აპლიკაცია ცვლილებებს ავტომატურად გადაიტანს ერთი მოწყობილობიდან მეორეზე **თქვენი პირადი GitHub Gist-ის** მეშვეობით (უფასოა).

### დაკავშირება (ორივე მოწყობილობაზე ერთნაირად)

1. გახსენით [github.com/settings/tokens](https://github.com/settings/tokens) → **Generate new token (classic)**.
2. სახელი: „family-budget", ვადა: „No expiration", უფლება: მხოლოდ **`gist`**.
3. **Generate token** → დააკოპირეთ კოდი (`ghp_...`) — ის მხოლოდ ერთხელ ჩანს, შეინახეთ უსაფრთხოდ.
4. აპში: **პარამეტრები → სინქრონიზაცია** → ჩასვით token → **„დაკავშირება"**.
5. მეორე მოწყობილობაზე იგივე: მხოლოდ token და „დაკავშირება". **Gist ID-ის ჩაწერა აღარ არის საჭირო** — აპი თავად პოულობს არსებულს.

### ნინოს დაკავშირება

1. გიორგის GitHub-ში შექმენით ნინოსთვის **ცალკე** token: [ბმული](https://github.com/settings/tokens/new?scopes=gist&description=family-budget-nino) (gist უკვე მონიშნულია) → „No expiration" → Generate.
2. ნინოს ტელეფონზე: `https://bagdadishvili.github.io/SalEx/` → მთავარ ეკრანზე დამატება → პარამეტრები → სინქრონიზაცია → token → „დაკავშირება".
3. ტელეფონი თუ დაიკარგა — GitHub-ში მხოლოდ ნინოს token-ს წაშლით.

### როგორ იცავს სინქრონიზაცია მონაცემებს

- **გაერთიანება, არა გადაწერა:** ორი ადამიანის ცვლილებები ერთიანდება ჩანაწერ-ჩანაწერ (თითო შაბლონი/ტრანზაქცია/თვის შემოსავალი/კურსი ცალკე). თუ გიორგიმ ხელფასი შეცვალა და ნინომ იმავდროულად ხარჯი ჩაწერა — ორივე შენარჩუნდება. ჩანაწერი ქრება მხოლოდ მაშინ, თუ ვინმემ ის მართლა წაშალა.
- ახალი/ცარიელი მოწყობილობა ღრუბლის მონაცემებს ვერ წაშლის — უბრალოდ იღებს მათ.
- თუ ატვირთვა ან ჩამოტვირთვა მონაცემებს მკვეთრად შეამცირებდა (მაგ. 80 ჩანაწერი → 0), ავტომატური სინქრონიზაცია **ჩერდება** და ყვითელ ზოლში გეკითხებათ, რომელი ვერსია დატოვოთ.
- თუ ორივე მოწყობილობაზე სხვადასხვა მონაცემია, აპი არ გამოიცნობს — გკითხავთ.
- ღრუბელში ყოველი ატვირთვა ცალკე ვერსიად ინახება → **პარამეტრები → აღდგენის წერტილები → ღრუბლის ისტორია**. დამატებით, დღეში ერთხელ Gist-ში იწერება ცალკე ფაილი `backup-წელი-თვე.json`. ხელით: **„☁️ ღრუბელში შენახვა ახლავე"**.
- სათაურთან პატარა წერტილი: 🟢 სინქრონშია, 🟠 მიმდინარეობს, 🔴 შეცდომა ან გადაწყვეტილება საჭიროა.

**token-ი არასდროს გადადის JSON/CSV ბექაფებში** — ის ცალკე ინახება თითოეულ მოწყობილობაზე.

## რას აკეთებს აპლიკაცია

ყოველი თვისთვის პასუხობს ოთხ კითხვას:

### გვერდები

- **დეშბორდი** — არჩეული თვის სრული სურათი კომპაქტურ ბარათებად; 🌐 ღილაკით დღევანდელი ოფიციალური კურსი; ქვემოთ „დაგეგმილი vs რეალური" და **წლიური მიმოხილვა** (შემოსავალი/ხარჯი/დანაზოგი/ნაშთი თვეების მიხედვით). აპი იხსენებს, რომელ თვეზე იყავით ბოლოს; „დღეს" ღილაკი აბრუნებს მიმდინარე თვეზე.
- **ტრანზაქციები** — ყველა გადახდის სია, ფილტრებით (სტატუსი, პასუხისმგებელი პირი).
- **შაბლონები** — განმეორებადი გადახდები (ქირა, კომუნალური, დაზღვევა და ა.შ.), რომლებიც ავტომატურად გენერირდება ყოველ თვეს.
- **კატეგორიები** — თავისუფლად დასამატებელი/სარედაქტირებელი/წასაშლელი კატეგორიები, თითოეული მიბმულია ბიუჯეტის კატეგორიაზე (იხ. პარამეტრები) და, სურვილისამებრ, მონიშნულია როგორც „საქართველოში გადასარიცხი".
- **პარამეტრები** — ბიუჯეტის კატეგორიების (ე.წ. „bucket") მართვა — სახელი, სამიზნე პროცენტი, ფერი, დამატება/წაშლა; თავისუფალი თანხის გიორგი/ნინო განაწილება; გარეგნობა (თემა, აქცენტის ფერი, ფონტი); სინქრონიზაცია; მონაცემების ექსპორტი/იმპორტი.

### ბიუჯეტის კატეგორიები („buckets")

ნაცვლად ფიქსირებული ოთხი ბაკეტისა, აპლიკაცია საშუალებას გაძლევთ თავად განსაზღვროთ რამდენი და რა სახის ბიუჯეტის კატეგორია გაქვთ (მაგ. „აუცილებელი", „დანაზოგი", ან ნებისმიერი სხვა, თქვენი შექმნილი). თითოეულს აქვს სახელი, სამიზნე პროცენტი და ფერი — ცვლილება დაუყოვნებლივ აისახება დეშბორდზე. საქართველოში გადასარიცხი თანხა ცალკე პროცენტს **აღარ** მოითხოვს — ის უბრალოდ აღინიშნება კატეგორიის დონეზე (checkbox) და ცალკე ჩანს დეშბორდზე საინფორმაციოდ, ხოლო ბიუჯეტის გათვლებში ითვლება იმ კატეგორიაში, რომელშიც რეალურად მიაკუთვნეთ (ჩვეულებრივ — „აუცილებელი").

## ტექნიკური დეტალები (დეველოპერებისთვის)

- სუფთა statik საიტი: `index.html` + vanilla JS (ES მოდულები) + CSS. Build-ი, framework და backend არ სჭირდება.
- მონაცემები ინახება `localStorage`-ში, გასაღების `familyBudget.v1` ქვეშ, ერთი JSON ობიექტის სახით (`js/state.js`, სქემის ვერსია 4 — ერთიანი კატეგორიები `parentId`-ით, `account` ველი, ბიუჯეტის ტრანზაქციები `kind: 'envelope'` + `spends[]`, ჩანაწერების დროის შტამპები `_u`/`_uf` და წაშლის კვალი `deleted` გაერთიანებისთვის — `js/records.js`). ახალი/არარედაქტირებული მდგომარეობის `updatedAt` = 1970, რომ სინქრონიზაციისას არასდროს „გაიმარჯვოს". ცვლილების გარეშე `updateState` არაფერს ინახავს.
