# ოჯახის ბიუჯეტი

ოჯახის ბიუჯეტის დაგეგმვისა და კონტროლის აპლიკაცია გიორგისა და ნინოსთვის — შემოსავალი, გერმანიაში აუცილებელი ხარჯები, საქართველოში გადასარიცხი თანხები (₾ → €), დანაზოგი და თითოეულის თავისუფალი ფული, ერთ ეკრანზე.

აპლიკაცია მთლიანად მუშაობს ბრაუზერში — **არ სჭირდება საკუთარი სერვერი თუ ბაზა**. მონაცემები ინახება თქვენივე ბრაუზერში (`localStorage`), ხოლო სურვილის შემთხვევაში შეგიძლიათ ჩართოთ **ავტომატური სინქრონიზაცია** კომპიუტერსა და სმარტფონს შორის (იხ. ქვემოთ).

---

## ⚠️ მნიშვნელოვანი გაფრთხილება

**თქვენი მონაცემები ნაგულისხმევად ინახება მხოლოდ ამ ბრაუზერში, ამ მოწყობილობაზე.** თუ წაშლით ბრაუზერის მონაცემებს, გამოიყენებთ სხვა მოწყობილობას ან ბრაუზერს (და სინქრონიზაცია ჩართული არ გაქვთ), ან რამე მოხდება მოწყობილობასთან — მონაცემები დაიკარგება, თუ წინასწარ არ გექნებათ **JSON ბექაფი** გაკეთებული.

➡️ რეგულარულად გააკეთეთ **პარამეტრები → მონაცემები → JSON ექსპორტი**. აპლიკაცია თავად შეგახსენებთ, თუ 30 დღეზე მეტია ბექაფი არ გაგიკეთებიათ. სინქრონიზაციის ჩართვა ამ საჭიროებას ამცირებს, მაგრამ არ ანაცვლებს — JSON ბექაფი მაინც ღირს.

## GitHub Pages-ზე გამოქვეყნება (ნაბიჯ-ნაბიჯ, არაპროგრამისტისთვის)

1. შექმენით ახალი **repository** თქვენს GitHub ანგარიშზე (მაგ. `family-budget`).
2. ატვირთეთ ამ საქაღალდის ყველა ფაილი და ქვესაქაღალდე repository-ის root-ში (ანუ `index.html` პირდაპირ repo-ს ძირში, არა ქვესაქაღალდეში).
   - შეგიძლიათ გამოიყენოთ GitHub-ის ვებ ინტერფეისის „Add file → Upload files" ღილაკი, ან `git push`, თუ იცით როგორ.
3. გადადით repository-ის **Settings** ჩანართზე.
4. მარცხენა მენიუში აირჩიეთ **Pages**.
5. **„Build and deployment"** სექციაში, **Source**-ში აირჩიეთ **„Deploy from a branch"**.
6. **Branch**-ში აირჩიეთ `main` (ან რომელ branch-ზეც ატვირთეთ ფაილები) და საქაღალდედ — **`/ (root)`**. დააჭირეთ **Save**.
7. დაელოდეთ 1-2 წუთს — GitHub ავტომატურად გამოაქვეყნებს საიტს. გვერდის ზედა ნაწილში გამოჩნდება ბმული სახით: `https://<თქვენი-username>.github.io/<repo-სახელი>/`.
8. გახსენით ეს ბმული — აპლიკაცია მზადაა! შეგიძლიათ დაამატოთ ტელეფონის მთავარ ეკრანზეც (Android-ზე Chrome-ში: მენიუ → „Add to Home screen").

**შენიშვნა:** თუ დააკოპირებთ ან გადაარქმევთ repository-ს, ან შეცვლით მისამართს, ბრაუზერი ამას აღიქვამს, როგორც ახალ საიტს — ძველი localStorage მონაცემები ახალ მისამართზე არ გადაინაცვლებს. ამიტომაც მნიშვნელოვანია JSON ბექაფი და/ან სინქრონიზაცია.

## 🔄 სინქრონიზაცია კომპიუტერსა და სმარტფონს შორის

აპლიკაცია ცვლილებებს ავტომატურად გადაიტანს ერთი მოწყობილობიდან მეორეზე **თქვენი პირადი GitHub Gist-ის** მეშვეობით (უფასოა).

### დაკავშირება (ორივე მოწყობილობაზე ერთნაირად)

1. გახსენით [github.com/settings/tokens](https://github.com/settings/tokens) → **Generate new token (classic)**.
2. სახელი: „family-budget", ვადა: „No expiration", უფლება: მხოლოდ **`gist`**.
3. **Generate token** → დააკოპირეთ კოდი (`ghp_...`) — ის მხოლოდ ერთხელ ჩანს, შეინახეთ უსაფრთხოდ.
4. აპში: **პარამეტრები → სინქრონიზაცია** → ჩასვით token → **„დაკავშირება"**.
5. მეორე მოწყობილობაზე იგივე: მხოლოდ token და „დაკავშირება". **Gist ID-ის ჩაწერა აღარ არის საჭირო** — აპი თავად პოულობს არსებულს.

### ნინოს დაკავშირება (ბმულით)

ნინოს **GitHub-ის ანგარიში არ სჭირდება** — მონაცემები გიორგის ანგარიშზეა; ნინოს სჭირდება მხოლოდ საკუთარი „გასაღები" (token), რომელიც გიორგის GitHub-ში იქმნება.

1. გიორგის ტელეფონზე/კომპიუტერზე: **პარამეტრები → სინქრონიზაცია → „📲 ნინოს ტელეფონის დაკავშირება"** → „1) ნინოსთვის token-ის შექმნა" (GitHub გაიხსნება, „gist" უკვე მონიშნულია) → Expiration „No expiration" → „Generate token" → დააკოპირეთ.
2. ჩასვით აპში → „3) ბმულის შექმნა" → „📤 გაგზავნა ნინოსთვის" (პირად ჩატში).
3. ნინო ხსნის ბმულს თავის ტელეფონზე → „დაკავშირება" → მზადაა (აპი ავტომატურად წაშლის გასაღებს მისამართის ზოლიდან). მერე: მთავარ ეკრანზე დამატება.
4. ტელეფონი თუ დაიკარგა: GitHub → Settings → Developer settings → Personal access tokens → წაშალეთ მხოლოდ ნინოს token.

### როგორ იცავს სინქრონიზაცია მონაცემებს

- **გაერთიანება, არა გადაწერა:** ორი ადამიანის ცვლილებები ერთიანდება ჩანაწერ-ჩანაწერ (თითო შაბლონი/ტრანზაქცია/თვის შემოსავალი/კურსი ცალკე). თუ გიორგიმ ხელფასი შეცვალა და ნინომ იმავდროულად ხარჯი ჩაწერა — ორივე შენარჩუნდება. ჩანაწერი ქრება მხოლოდ მაშინ, თუ ვინმემ ის მართლა წაშალა.
- ახალი/ცარიელი მოწყობილობა ღრუბლის მონაცემებს ვერ წაშლის — უბრალოდ იღებს მათ.
- თუ ატვირთვა ან ჩამოტვირთვა მონაცემებს მკვეთრად შეამცირებდა (მაგ. 80 ჩანაწერი → 0), ავტომატური სინქრონიზაცია **ჩერდება** და ყვითელ ზოლში გეკითხებათ, რომელი ვერსია დატოვოთ.
- თუ ორივე მოწყობილობაზე სხვადასხვა მონაცემია, აპი არ გამოიცნობს — გკითხავთ.
- ღრუბელში ყოველი ატვირთვა ცალკე ვერსიად ინახება → **პარამეტრები → აღდგენის წერტილები → ღრუბლის ისტორია**. დამატებით, დღეში ერთხელ Gist-ში იწერება ცალკე ფაილი `backup-წელი-თვე.json`. ხელით: **„☁️ ღრუბელში შენახვა ახლავე"**.
- სათაურთან პატარა წერტილი: 🟢 სინქრონშია, 🟠 მიმდინარეობს, 🔴 შეცდომა ან გადაწყვეტილება საჭიროა.

**token-ი არასდროს გადადის JSON/CSV ბექაფებში** — ის ცალკე ინახება თითოეულ მოწყობილობაზე.

## 🛟 მონაცემების დაცვა და აღდგენა

**სად ინახება ბექაფები:** „JSON ექსპორტი" → ფაილი `family-budget-backup-…json` მოწყობილობის **Downloads** საქაღალდეში; „📤 ბექაფის გაზიარება" → პირდაპირ Google Drive-ში/ფოსტაში (ტელეფონზე); ავტომატური აღდგენის წერტილები → ბრაუზერში (პარამეტრები → 🛟); ღრუბელი → **gist.github.com** → „Family Budget app data" (ყველა ვერსია „Revisions"-ში).


- **არასდროს გაასუფთაოთ ბრაუზერის „საიტის მონაცემები" (Clear site data / cookies and site data) ამ საიტისთვის** — ეს შლის აპის ყველა მონაცემს ამ მოწყობილობაზე. განახლებისთვის ეს საჭირო აღარ არის: აპი ახალ ვერსიას თავად ტვირთავს.
- ტელეფონზე დაამატეთ აპი **მთავარ ეკრანზე** (iPhone: Safari → გაზიარება → „Add to Home Screen"; Android: Chrome მენიუ → „Install app"). ასე ბრაუზერი მონაცემებს თავისით არ შლის.
- აპი ავტომატურად ინახავს **აღდგენის წერტილებს**: ყოველდღე და ყოველი სარისკო მოქმედების წინ (იმპორტი, სინქრონიზაციით ჩანაცვლება, წაშლა, აღდგენა). **პარამეტრები → აღდგენის წერტილები**.
- თუ მონაცემები დაიკარგა: 1) სცადეთ ამ მოწყობილობის ასლები; 2) თუ სინქრონიზაცია ოდესმე ყოფილა ჩართული — **„ღრუბლის ისტორიის ჩატვირთვა"**, იპოვეთ ბოლო ვერსია, სადაც შაბლონები/ტრანზაქციები ჩანს, და **„აღდგენა"**; 3) JSON ბექაფიდან იმპორტი.
- JSON ექსპორტი თვეში ერთხელ მაინც — ეს ერთადერთი ასლია, რომელიც ბრაუზერისგან სრულიად დამოუკიდებელია.
- **აღდგენის წერტილების სიაში** თითო ასლს აქვს სტატუსი: „☁️ გაგზავნილია" (თუ ის „📤" ღილაკით გააზიარეთ, მაგ. Google Drive-ში) ან „📱 მხოლოდ ამ მოწყობილობაზე". 🗑 შლის ასლს მხოლოდ ამ მოწყობილობიდან (Drive-ში გაგზავნილი ფაილი რჩება). შენიშვნა: ბრაუზერი ვერ ხედავს Drive-ს — „გაგზავნილია" ნიშნავს, რომ გაზიარების ფანჯარა წარმატებით დასრულდა.

## 🔄 აპის განახლება და თქვენი მონაცემები

- ახალი ვერსიის ატვირთვა **მონაცემებს არ ეხება**: ისინი ინახება თქვენს მოწყობილობაზე (და ღრუბელში, თუ სინქრონიზაცია ჩართულია), არა GitHub-ის კოდში.
- თუ ახალ ვერსიას მონაცემების ფორმატის შეცვლა სჭირდება, აპი **გადაყვანამდე** ავტომატურად ინახავს ძველ მონაცემებს ორჯერ: აღდგენის წერტილი „აპის განახლებამდე" (პარამეტრები → აღდგენის წერტილები) და ცალკე ასლი ბრაუზერში. გადაყვანა ტესტებით მოწმდება: ყველა ტრანზაქცია, გადახდა, კურსი და ჯამი უცვლელი რჩება.
- სინქრონიზაციისას ძველი ვერსიის მოწყობილობიდან მოსული მონაცემებიც ჯერ ახალ ფორმატში გადაიყვანება და მერე ერთიანდება.
- აპის ვერსია ჩანს პარამეტრების ბოლოში.

## 👆 ბარათზე დაჭერა = მისი ხარჯები იქვე

- მიმდინარე თვის კურსი ავტომატურად ახლდება (თუ ხელით არ ჩაგიწერიათ); 🏦 ღილაკი — ახლავე განახლება. ლარში გადახდისას ფანჯარაში შეგიძლიათ ჩაწეროთ ზუსტი კურსი, რომლითაც გადაცვალეთ — ის შემდეგ აღარ შეიცვლება.
- **პირველად:** ატვირთვის შემდეგ GitHub-ზე → რეპოზიტორია → **Actions** → „Bank of Georgia EUR rate" → **Run workflow** (ან დაელოდეთ 10 წუთს). სანამ `rates` branch შეიქმნება, აპი დროებით ოფიციალურ კურსს აჩვენებს და ამას წერს.

## რას აკეთებს აპლიკაცია

ყოველი თვისთვის პასუხობს ოთხ კითხვას:

1. რამდენი შემოსავალი შემოვიდა (გიორგის + ნინოს ხელფასი)?
2. რამდენი მიდის აუცილებელ ხარჯებზე გერმანიაში და რამდენი უნდა გაიგზავნოს საქართველოში (₾ → €)?
3. რამდენს ვზოგავთ ამ თვეს (გეგმა vs ფაქტი)?
4. რამდენი თავისუფალი ფული რჩება ცალ-ცალკე გიორგისთვის და ნინოსთვის?

### გვერდები

- **დეშბორდი** — არჩეული თვის სრული სურათი კომპაქტურ ბარათებად; 🌐 ღილაკით დღევანდელი ოფიციალური კურსი; ქვემოთ „დაგეგმილი vs რეალური" და **წლიური მიმოხილვა** (შემოსავალი/ხარჯი/დანაზოგი/ნაშთი თვეების მიხედვით). აპი იხსენებს, რომელ თვეზე იყავით ბოლოს; „დღეს" ღილაკი აბრუნებს მიმდინარე თვეზე. სხვა გვერდიდან დაბრუნებისას დეშბორდი იმავე ადგილას იხსნება, სადაც დატოვეთ.
- **ტრანზაქციები** — ყველა გადახდის სია, ფილტრებით (სტატუსი, პასუხისმგებელი პირი).
- **შაბლონები** — განმეორებადი გადახდები (ქირა, კომუნალური, დაზღვევა და ა.შ.), რომლებიც ავტომატურად გენერირდება ყოველ თვეს.
- **კატეგორიები** — თავში **🎯 გეგმა**: თითო კატეგორიის და თავისუფალი თანხის მიზანი % ან €-ში (იხ. ზემოთ). ქვემოთ — თავისუფლად დასამატებელი/სარედაქტირებელი/წასაშლელი კატეგორიები, თითოეული მიბმულია ბიუჯეტის კატეგორიაზე (იხ. პარამეტრები) და, სურვილისამებრ, მონიშნულია როგორც „საქართველოში გადასარიცხი".
- **პარამეტრები** — გარეგნობა (თემა, აქცენტის ფერი, ფონტი); სინქრონიზაცია; მონაცემების ექსპორტი/იმპორტი.

### ბიუჯეტის კატეგორიები („buckets")

ნაცვლად ფიქსირებული ოთხი ბაკეტისა, აპლიკაცია საშუალებას გაძლევთ თავად განსაზღვროთ რამდენი და რა სახის ბიუჯეტის კატეგორია გაქვთ (მაგ. „აუცილებელი", „დანაზოგი", ან ნებისმიერი სხვა, თქვენი შექმნილი). თითოეულს აქვს სახელი, მიზანი (% ან €, „კატეგორიები → 🎯 გეგმა") და ფერი — ცვლილება დაუყოვნებლივ აისახება დეშბორდზე. საქართველოში გადასარიცხი თანხა ცალკე პროცენტს **აღარ** მოითხოვს — ის უბრალოდ აღინიშნება კატეგორიის დონეზე (checkbox) და ცალკე ჩანს დეშბორდზე საინფორმაციოდ, ხოლო ბიუჯეტის გათვლებში ითვლება იმ კატეგორიაში, რომელშიც რეალურად მიაკუთვნეთ (ჩვეულებრივ — „აუცილებელი").

## ტექნიკური დეტალები (დეველოპერებისთვის)

- სუფთა statik საიტი: `index.html` + vanilla JS (ES მოდულები) + CSS. Build-ი, framework და backend არ სჭირდება.
- მონაცემები ინახება `localStorage`-ში, გასაღების `familyBudget.v1` ქვეშ, ერთი JSON ობიექტის სახით (`js/state.js`, სქემის ვერსია 5 — `toGeorgia` ნიშანი ჩანაწერზე, ერთი „ვინ იხდის" ველი (`account`); ერთიანი კატეგორიები `parentId`-ით, `account` ველი, ბიუჯეტის ტრანზაქციები `kind: 'envelope'` + `spends[]`, ჩანაწერების დროის შტამპები `_u`/`_uf` და წაშლის კვალი `deleted` გაერთიანებისთვის — `js/records.js`). ახალი/არარედაქტირებული მდგომარეობის `updatedAt` = 1970, რომ სინქრონიზაციისას არასდროს „გაიმარჯვოს". ცვლილების გარეშე `updateState` არაფერს ინახავს.
- სინქრონიზაციის token/Gist ID ინახება ცალკე გასაღებში (`familyBudget.sync.v1`), რომ არასდროს მოხვდეს JSON/CSV ექსპორტში (`js/sync.js`).
